## 已固定的产品规则

后续实现不得改变以下基础规则，除非另行评审并同步服务端、前端和部署文档。

### 试用额度

- 匿名设备每天最多成功生成 10 张图片。
- 同一来源地址每天最多成功生成 30 张图片。
- 配额日按 `Asia/Shanghai` 计算，并在北京时间次日零点重置。
- 单次请求允许生成 1–4 张。
- 调用上游前预占，完成后只按实际成功图片数扣减。
- 失败、超时和未执行的槽位不消耗成功额度。
- 第一阶段不增加 CAPTCHA，也不设置全站每日图片总量上限。

### 幂等和状态机

- 客户端每次批次请求必须携带 `requestKey`。
- 同一设备、同一 `requestKey`、相同语义载荷是重放，不重复预占或调用上游。
- 同一 `requestKey` 对应不同载荷或不同数量时返回 `IDEMPOTENCY_CONFLICT`，HTTP 状态为 409。
- 只有成功取得 `claimForExecution` 的调用方可以访问上游供应商。
- 只有本次结算返回 `settled` 时，临时图片才能交付给客户端。
- `expired` 是不可逆终态；超时后的迟到图片必须丢弃。
- 服务端不长期保存生成图片，因此已完成请求重放时不能伪造图片恢复结果。

### 数据和隐私

- 服务端不长期保存图片、提示词或参考图。
- 上游地址、密钥和真实模型标识只存在于服务端配置中。
- 公众前端不得包含或发送 `baseUrl`、`apiKey`、真实模型 ID。
- 日志不得包含 Cookie、提示词、图片、明文 IP、数据库连接串、上游密钥或供应商响应正文。
- 用户作品仍保存在浏览器本地；清除浏览器数据或更换设备不会自动同步。

### 双模式兼容

项目当前同时支持：

- `public`：公众免费生图，通过同源服务端接口调用，裁剪不适合公众开放的能力。
- `self-hosted`：保留当前浏览器直连用户自有渠道的行为。

公众模式的实现不能破坏现有自部署模式。

## 已实现阶段一：输入校验和上游供应商客户端

该阶段已经作为图片路由的前置能力落地，并由模块测试和本地 HTTP fake provider 覆盖；真实供应商兼容性仍需外部验收。

### 输入校验需求

- 提示词不能为空，最长 4000 字符。
- 数量必须为 1–4 的安全整数。
- 比例和质量必须来自服务端白名单。
- 参考图最多 4 张。
- 单张参考图不超过 10MB，总量不超过 20MB。
- 只允许 JPEG、PNG 和 WebP。
- 必须根据真实文件内容识别格式，不能信任文件名或客户端 MIME。
- 必须读取解码后的宽高；总像素不超过 8,294,400，最长边不超过 3840。
- 不接受用户提供的任意远程图片 URL。

当前由独立模块提供：

```ts
validateGenerationInput(...)
validateReferenceImages(...)
```

真实格式可使用 `file-type` 检查，宽高可使用 `sharp(...).metadata()` 读取；无需为了校验而重新编码图片。

### 上游客户端需求

当前 `ImageProvider` 接口支持单槽位文生图和参考图编辑：

```ts
type ProviderImage = {
  mimeType: string;
  data: string;
};

interface ImageProvider {
  generateSlot(input: {
    prompt: string;
    size: string;
    quality: string;
    signal: AbortSignal;
  }): Promise<ProviderImage>;

  editSlot(input: {
    prompt: string;
    size: string;
    quality: string;
    references: File[];
    signal: AbortSignal;
  }): Promise<ProviderImage>;
}
```

实现要求：

- 服务端固定上游 URL、密钥和模型，不接受客户端覆盖。
- 上游统一要求返回 base64 图片。
- 限制上游响应最大体积。
- 401、429、5xx、超时、空响应和非法图片均转换为受控错误。
- 外部只暴露 `PROVIDER_REJECTED`、`PROVIDER_TIMEOUT` 或 `SERVICE_UNAVAILABLE`。
- 不向客户端或日志复制完整供应商响应。

### 自动化与外部验收

仓库自动化覆盖空提示词、超长提示词、非法数量、未知比例和质量、参考图数量与体积超限、伪装文件、超像素图片，以及本地 HTTP 上游成功、401、429、500、超时和空图片。真实供应商的协议差异、余额与限流行为仍需在受控测试账号上验证。

## 已实现阶段二：图片路由和生成编排

当前提供两个写接口：

```text
POST /api/images/generations
POST /api/images/edits
```

### 请求契约

文生图使用 JSON，编辑使用 multipart。两者都包含：

- `requestKey`
- `prompt`
- `count`
- `size`
- `quality`

编辑请求额外包含最多 4 个参考图文件。

### 执行顺序

每次请求必须严格执行：

1. 检查公众生图开关和请求来源。
2. 校验字段和参考图。
3. 按固定 v1 协议计算 HMAC-SHA-256 载荷指纹。
4. 调用 `reserveQuota`。
5. 调用 `claimForExecution`。
6. 只有 `claimed` 才并发执行图片槽位。
7. 所有槽位共享一次请求级超时控制器。
8. 使用 `Promise.allSettled` 汇总每个槽位。
9. 即使客户端断开，也必须完成一次结算尝试。
10. 只有 `settled` 才返回临时图片；`expired` 时丢弃图片。

### 重放契约

- 仍在执行的相同请求重放：返回 202 和当前状态，不再次调用供应商。
- 已结束的相同请求重放：返回 200、`results: []`、`replayed: true` 和当前额度。
- 不同载荷重用 key：返回 409。

### 响应契约

每个槽位独立成功或失败，部分成功的整个批次仍返回 200：

```json
{
  "index": 0,
  "status": "success",
  "image": {
    "mimeType": "image/png",
    "data": "base64..."
  }
}
```

```json
{
  "index": 1,
  "status": "failed",
  "errorCode": "PROVIDER_REJECTED"
}
```

批次响应必须同时返回服务端最新额度快照，前端不能自行推算剩余额度。

### 关闭开关

`PUBLIC_GENERATION_ENABLED=false` 时：

- 图片写接口返回 `PUBLIC_GENERATION_OFF`。
- 不预占额度，不调用供应商。
- `/api/session`、额度查询、本地画布、素材、下载和导出仍可使用。

### 自动化与外部验收

生成编排和路由自动化覆盖额度失败不调用上游、4 槽中 2 成功只按 2 结算、重放不重复调用、幂等冲突映射 409、超时后仍结算，以及结算过期或异常时不交付临时图片。真实 PostgreSQL 失败、客户端断连和迟到网络响应仍需端到端环境验证。

## 已实现阶段三：过期回收调度、健康检查和服务端镜像

### 回收调度

额度服务和进程入口均已接入有界回收：

- 服务监听前先回收一次。
- 之后每 60 秒运行一轮。
- 每轮最多扫描 100 条。
- 单条计数不一致记录受控日志后继续。
- 数据库等系统错误立即结束本轮，但不终止服务进程。
- 进程退出时清理定时器并关闭数据库连接。

以上代码路径已实现；容器或进程重启后的真实恢复、长期运行和异常数据库状态仍需部署环境验收。

### 健康接口

```text
GET /health/live
GET /health/ready
```

- `live` 始终返回 200 和 `{ "status": "ok" }`。
- `ready` 只检查数据库和关键配置；正常返回 200，数据库不可用返回 503。
- 健康检查绝不能访问付费供应商。

### 服务端镜像

已提供独立 `server/Dockerfile` 和 `.dockerignore`：

- 使用固定 Bun 基础镜像。
- 仅复制服务端包、锁文件、源码和迁移。
- 使用非 root 用户运行。
- 暴露容器内部端口 3001。
- 容器健康检查访问 `/health/live`。
- 镜像中不包含前端或任何真实密钥。

## 已实现阶段四：前端公众模式

### 部署模式和能力矩阵

当前使用明确模式：

```ts
type AppMode = "public" | "self-hosted";
```

- `VITE_APP_MODE` 缺省为 `self-hosted`。
- 能力判断集中在统一矩阵，不在组件中散落环境变量判断。
- `public` 仅开放图片生成、画布、素材和提示词库。
- `public` 禁用视频、音频、文本生成、WebDAV、Codex/Agent 和渠道配置。
- `self-hosted` 保持当前行为。

公众裁剪必须发生在路由和能力层，不能只用 CSS 隐藏。

### 会话和额度状态

需要统一 store 管理：

- 首次加载调用 `/api/session`。
- 页面恢复到前台或生成后可调用 `/api/quota`。
- 并发初始化只发送一次请求。
- Cookie 被阻止或初始化失败时仍允许浏览，但禁用生成并显示明确提示。
- 每次使用服务端返回的完整快照覆盖本地额度状态。

### 统一生图客户端

页面和画布必须复用同一接口：

```ts
generateImages(input): Promise<GenerationBatch>
generateSingleImage(input): Promise<GeneratedImageResult>
```

- `public` 只访问相对路径 `/api/images/generations` 或 `/api/images/edits`。
- `public` 请求不携带上游地址、密钥或模型名。
- `self-hosted` 继续复用现有浏览器直连服务，并转换为同一批次结果类型。
- 公众模式不支持的蒙版上游编辑必须明确禁用，不能偷偷回退到浏览器直连。

### 路由和导航

公众模式：

- `/` 重定向到 `/image`。
- 只注册图片、画布、素材、提示词库和画布项目路由。
- 不注册 `/video` 和 `/config`。
- 不挂载 Agent 面板，不显示 Codex 状态或渠道配置入口。

### 生图工作台

- 一次操作对应一次服务端批次请求，而不是页面逐槽直连供应商。
- 数量、比例和质量来自 `/api/session` 白名单。
- 常驻显示今日剩余额度。
- 额度不足或所选数量超过剩余额度时禁止生成。
- 部分成功图片正常保存到 IndexedDB 和生成记录。
- 失败槽位重试使用新的 `requestKey`。
- 明确区分设备额度耗尽、共享网络额度耗尽和公众生成关闭。
- 公众模式隐藏模型选择器和渠道设置动作。

### 画布生图

- 图片生成、参考图编辑和失败重试统一走 `generateSingleImage`。
- 公众模式只保留图片、文本和图片配置节点。
- 隐藏视频、音频、文本问答和 Agent 相关节点与动作。
- 额度不足时不得先创建加载节点。
- 每次完成后应用服务端额度快照。
- 裁剪、分割等纯本地图片操作继续可用。

## 已配置阶段六：部署、安全和运维

双容器、Nginx、Cloudflare 可信地址 include 和运维脚本已落地。镜像构建、Compose 展开和 Nginx 语法由 CI 提供静态门禁；真实域名、网络、防火墙、TLS、限流和告警链路仍待外部验收。

### 双容器拓扑

生产部署配置为：

```text
Cloudflare -> web/Nginx -> api/Bun -> 现有 PostgreSQL
```

- `web` 是唯一公开端口。
- `api` 只在 Docker 私有网络监听 3001，不映射宿主端口。
- 不新增 PostgreSQL 容器，复用服务器现有 PostgreSQL。
- 数据库使用独立、最小权限账号。
- 公众前端构建传入 `VITE_APP_MODE=public`。
- api 使用运行时环境文件，前端镜像不包含供应商密钥。

### Cloudflare 和源站保护

只有在源站防火墙限制为 Cloudflare 官方地址段后，应用才能信任 `CF-Connecting-IP`。

必须满足：

- Cloudflare 代理开启并使用严格 TLS。
- 源站 80/443 仅允许 Cloudflare 官方 IPv4/IPv6 地址段。
- Nginx 仅信任这些网段并恢复真实来源地址。
- SSH 和 PostgreSQL 不向公网开放。
- 不能通过源站 IP 绕过 Cloudflare。

### Nginx

图片接口要求：

```nginx
limit_req_zone $binary_remote_addr zone=image_api:10m rate=5r/m;
limit_req_status 429;
client_max_body_size 22m;
proxy_read_timeout 190s;
```

- 图片写接口使用 `burst=2 nodelay`。
- `/api/` 和 `/health/` 反代到 `api:3001`。
- 传递 `Host`、`X-Forwarded-Proto`、`CF-Connecting-IP` 和 `Cf-Ray`。
- API 禁止缓存，`index.html` 不做长缓存，静态资源可长缓存。
- CSP 不能阻止本地 Blob 图片预览。

### 日志和告警

结构化日志允许包含：

- `requestId`
- 内部 `clientId`
- 截断后的 `ipHashPrefix`
- `cfRay`
- `durationMs`
- `requestedCount`
- `successCount`
- 受控 `errorCode`

首期至少监控请求量、成功图片数、失败率、429、连续上游超时和供应商余额，并验证运行时关闭开关可以立即止损。

### 密钥和配置

- 聊天和调试阶段曾使用过的数据库密码在正式上线前必须轮换。
- 创建生产专用最小权限数据库账号。
- `ANON_TOKEN_SECRET`、`IP_HASH_SECRET`、`IDEMPOTENCY_SECRET` 和供应商密钥分别管理。
- 当前代码读取 `TIMEZONE`，部分旧设计写作 `QUOTA_TIMEZONE`；制作环境模板前必须统一名称，避免配置被忽略。

### 上线顺序

固定顺序为：

1. 设置 `PUBLIC_GENERATION_ENABLED=false`。
2. 备份数据库。
3. 显式执行迁移。
4. 启动 api 并检查 `/health/ready`。
5. 启动 web。
6. 执行不消耗图片额度的 smoke test。
7. 内部生成 1 张并核对账务。
8. 验证源站无法绕过、Nginx 限流有效。
9. 开放 Cloudflare 流量。
10. 设置 `PUBLIC_GENERATION_ENABLED=true`。

回滚时优先关闭生成，不应删除向后兼容迁移创建的数据。

## 当前开放顺序

应用代码与生产配置已完成，后续只按以下门禁推进：

1. 由 CI 运行完整 PostgreSQL 服务端测试、镜像构建、Compose 展开和 Nginx 语法检查。
2. 在受控环境验证真实供应商协议、余额、限流和错误映射。
3. 在测试域名执行数据库失败、客户端断连、迟到结果和进程/容器重启恢复。
4. 配置 Cloudflare Full (strict) 与源站防火墙，确认无法绕过代理。
5. 完成 iPhone Safari、Android Chrome 和桌面交互回归。
6. 保持 `PUBLIC_GENERATION_ENABLED=false` 小范围试运行，核对账务和日志后再开放生成。

公众接口不能仅凭代码、单元测试或静态 CI 对公网开放；源站保护、限流和运行时止损必须在真实部署中确认。
