# 公众生图部署

公众入口是独立于现有 `docker-compose.yml` 和 `docker-compose.local.yml` 的生产配置。它使用以下拓扑：

```text
Cloudflare -> web/Nginx -> api/Bun -> 既有 PostgreSQL
```

`web` 是唯一映射宿主端口的容器；`api` 仅通过 Compose 私有网络以端口 `3001` 被 `web` 访问。此配置不会创建 PostgreSQL 容器，也不应将 PostgreSQL 映射到公网。

> 仅当源站防火墙已经只允许 Cloudflare 官方网段访问 HTTPS 端口时，才可以信任 `CF-Connecting-IP`。本仓库的配置不会修改防火墙。

## 部署前条件

- Cloudflare 已为域名开启代理（橙云）并启用 **Full (strict)** TLS。
- 机器已有 PostgreSQL，且创建了仅授予本应用所需迁移和运行权限的独立数据库账号。
- PostgreSQL 容器已加入一个现有 Docker 网络，并在该网络中配置了稳定别名；公众 API 会加入该网络，前端容器不会加入。
- 源站 HTTPS 端口只允许 Cloudflare 官方 IPv4 / IPv6 网段访问；SSH 和 PostgreSQL 不向公网开放。
- 已创建 Cloudflare Origin Certificate，并可将证书和私钥以只读文件挂载到容器。
- 生产环境使用新的、彼此独立的 `ANON_TOKEN_SECRET`、`IP_HASH_SECRET` 和 `IDEMPOTENCY_SECRET`；曾在聊天或调试中使用过的数据库密码必须先轮换。

在 DNS、严格 TLS 与源站防火墙条件未同时满足前，不要公开启动此入口，也不要把 `PUBLIC_GENERATION_ENABLED` 设为 `true`。

## 准备配置

从模板创建运行时配置，保存在仓库根目录：

```bash
cp .env.public.example .env.public
```

至少填写：

- `PUBLIC_WEB_PORT`：通常为 `443`；这是 `web` 的唯一宿主端口。
- `PUBLIC_TLS_CERT_PATH`、`PUBLIC_TLS_KEY_PATH`：Origin Certificate 与私钥的绝对路径。
- `PUBLIC_ORIGIN`：例如 `https://canvas.example.com`，必须与浏览器 Origin 完全一致。
- `DATABASE_DOCKER_NETWORK`：既有 PostgreSQL 容器所在的 Docker 网络名称。该网络由外部维护，Compose 不会创建或删除。
- `DATABASE_URL`：连接到**既有** PostgreSQL 的生产专用最小权限账号；主机名使用 PostgreSQL 在上述网络中的别名，例如 `postgres`。
- `AI_BASE_URL`、`AI_API_KEY`、`AI_MODEL`：仅由 `api` 读取，绝不能写入前端构建参数。
- 三个独立的 32 字符以上密钥。

保持 `TIMEZONE=Asia/Shanghai`。首次上线时必须设为 `PUBLIC_GENERATION_ENABLED=false`，以便先完成不消耗额度的验证。

`.env.public` 已被 `.gitignore` 忽略，不能提交。不要将它传给前端构建、浏览器、工单或日志。

## Cloudflare 可信地址

Nginx 的 [`cloudflare-trusted.conf`](https://github.com/basketikun/infinite-canvas/blob/main/deploy/public/nginx/cloudflare-trusted.conf) 固定为 Cloudflare 官方地址段，只有这些来源可触发 `real_ip_header CF-Connecting-IP`。部署前刷新一次地址段：

```bash
./deploy/public/scripts/update-cloudflare-ips.sh
```

脚本直接从 Cloudflare 官方的 `ips-v4` 和 `ips-v6` 地址下载并生成 include 文件。刷新后应审阅并提交变更，再由基础设施管理员同步按相同官方地址段限制源站防火墙。更新 include **不等同于**配置防火墙，绝不能用它替代源站访问控制。

## 本地静态配置检查

不启动容器即可验证 Compose 展开、必填变量、外部数据库网络、TLS 文件路径、时区和生成开关：

```bash
./deploy/public/scripts/check-public-config.sh
```

该检查执行 `docker compose config --quiet`，不会启动、构建或部署服务。`docker-compose.public.yml` 使用两个服务：

- `api`：无 `ports`，只有 `expose: 3001`，同时加入前端私有网络和既有数据库网络，并使用 `server/Dockerfile` 的存活探针。
- `web`：以 `VITE_APP_MODE=public` 构建，唯一映射 `${PUBLIC_WEB_PORT}:443`；Nginx 将 `/api/`、`/health/` 转发到 `api:3001`。

只有 `api` 加入数据库网络。不要把 `web` 加入该网络，也不要为了容器连接继续将 PostgreSQL 端口映射到所有宿主地址。

Nginx 对两个图片写接口设置每真实来源地址 `5r/m`、`burst=2 nodelay`，请求体上限 22 MB、上游读超时 190 秒，并禁止 API 和健康响应缓存。`index.html` 不做长缓存，带哈希的静态文件缓存一年。CSP 明确允许 `img-src blob:`，以支持本地图片预览。

## 上线与回滚顺序

按以下顺序由具备服务器权限的运维人员操作：

1. 保持 `PUBLIC_GENERATION_ENABLED=false` 并备份数据库。
2. 审阅 `.env.public`、Cloudflare DNS/TLS 和源站防火墙规则；确认不能通过源站 IP 绕过 Cloudflare。
3. 运行配置检查。
4. 显式执行迁移：

   ```bash
   ./deploy/public/scripts/migrate-public.sh
   ```

5. 启动 Compose 服务后，通过 Cloudflare 域名运行不写图片接口的 smoke 检查：

   ```bash
   PUBLIC_ORIGIN=https://canvas.example.com ./deploy/public/scripts/smoke-public.sh
   ```

6. 由内部账号生成一张图片，核对额度账务、429 限流、错误日志和供应商余额。
7. 再次验证源站不可绕过；确认生产日志没有 Cookie、提示词、图片、明文 IP、连接串、密钥或供应商响应正文。
8. 仅在上述检查完成后，将 `PUBLIC_GENERATION_ENABLED=true`，再重建并滚动更新 `api`。

止损或回滚时，优先将 `PUBLIC_GENERATION_ENABLED=false` 并仅更新 `api`。不要删除已应用的向后兼容数据库迁移，也不要通过删除数据恢复服务。

## 日志安全检查

将容器或采集系统导出的日志保存为本地文件后运行：

```bash
./deploy/public/scripts/check-public-log-safety.sh /path/to/public-api.log
```

脚本会拦截常见 Cookie、授权头、连接串、API Key、提示词字段和原始 IP 模式。它是发布前的辅助门禁，不替代日志采集器字段审计；生产日志只应包含受控字段，例如 `requestId`、内部 `clientId`、截断后的 `ipHashPrefix`、`cfRay`、`durationMs`、数量统计和受控错误码。
