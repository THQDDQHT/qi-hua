# 公众免费生图与移动端适配设计

## 背景与目标

当前项目是一套以 Vite、React 和浏览器本地存储为基础的无限画布应用。生图请求由浏览器直接调用用户配置的 OpenAI 兼容接口，接口地址、密钥、画布、素材和生成记录都保存在浏览器本地。这种模式适合个人使用和自行部署，但不适合把站点直接开放给公众：服务端密钥无法隐藏，浏览器本地计数也无法形成可信的每日额度。

本次改造的目标是提供一个可在电脑和手机浏览器中使用的公众免费版：

- 不要求用户注册或登录。
- 每个匿名设备每天最多成功生成 10 张图片。
- 生成失败不扣额度，一次成功生成多张时按实际张数扣减。
- 每日额度按北京时间零点重置。
- 服务端隐藏上游接口地址和密钥，并阻止并发请求绕过额度。
- 第一阶段暂不启用人机验证，也不限制全站每日生成总量。
- 复用已有 PostgreSQL 和 OpenAI 兼容生图接口。
- 优先交付手机浏览器体验和可安装网页应用，后续再评估应用商店上架。
- 保留现有个人自部署模式，不删除浏览器直连能力。

## 范围与非目标

### 本次范围

- 新增轻量接口服务、匿名设备凭证、每日额度和生图代理。
- 新增公众部署模式，由服务端统一提供模型和生成参数范围。
- 改造生图工作台的桌面和手机布局。
- 补齐无限画布的核心触控交互。
- 增加网页应用清单、主屏幕安装和网页外壳缓存。
- 增加 Cloudflare、Nginx 和源站侧的基础防刷措施。
- 保留画布、素材和生成记录的浏览器本地存储方式。

### 非目标

- 不实现账号注册、登录、找回账号或跨设备同步。
- 不把画布、素材、提示词或生成图片保存到服务端。
- 不开放视频、音频、文本模型和本地 Codex 助手。
- 不引入 Redis、消息队列、微服务或独立任务平台。
- 不在第一阶段接入人机验证、浏览器指纹或风险评分。
- 不在第一阶段接入 Capacitor，也不发布 iOS 或 Android 商店版本。
- 不为全站设置每日图片总量上限，但必须保留快速关闭免费生图的运行时开关。

## 当前状态

当前 `web` 是纯静态 Vite 应用，根目录 Docker 镜像使用 Nginx 提供构建产物。`web/src/stores/use-config-store.ts` 在浏览器中持久化上游地址、密钥、渠道和模型；`web/src/services/api/image.ts` 直接请求上游生成与编辑接口；生成记录和图片 Blob 由 `localforage` 与 IndexedDB 保存。

现有生图页已经支持提示词、参考图、多张生成、失败重试、生成记录、图片下载、加入参考图和保存到素材。无限画布已经具备节点、连线、撤销重做、图片生成和素材插入，但交互主要按桌面鼠标设计。项目已有移动导航抽屉，但缺少完整的画布触控规则和手机端固定操作区。

现有代码中还包含视频、音频、文本问答、WebDAV、模型渠道配置和本地 Codex 助手。公众模式只隐藏这些入口和调用路径，不删除自部署模式所需代码。

## 核心对象与约束

### 匿名设备

匿名设备代表一个浏览器安装实例，不等同于自然人。首次访问公众接口时，服务端生成高强度随机令牌，通过 `HttpOnly`、`Secure`、`SameSite=Lax` Cookie 返回。数据库只保存令牌摘要，不保存原始令牌。

匿名设备凭证默认有效一年，可由服务端禁用。清除 Cookie 或更换浏览器会产生新设备，因此还需要网络地址额度作为辅助限制。系统不采集浏览器指纹。

### 配额日期

配额日期按 `Asia/Shanghai` 计算。系统不依赖零点定时任务清空计数，而是在每次请求时根据当前北京时间选择对应的日期记录。历史日期记录后续异步清理，不影响额度切换。

### 图片额度

设备额度固定为每天 10 张，网络地址额度固定为每天 30 张。两个额度都同时计算成功数和预占数，必须满足：

```text
成功数 + 预占数 + 本次请求数量 <= 每日额度
```

只有实际成功返回的图片计入成功数。失败、被上游拒绝和超时的图片释放预占。单次请求最多申请 4 张。

### 生成请求

生成请求是一次可幂等重放的额度结算单元。客户端为每次用户操作生成 `requestKey`；同一匿名设备重复提交相同 `requestKey` 时，服务端返回原请求状态或结果摘要，不再次预占和扣减。

请求状态为：

```text
reserved -> running -> completed
                    -> partial
                    -> failed
                    -> expired
```

## 数据模型

### `anonymous_clients`

```text
id              uuid primary key
token_hash      bytea unique not null
status          text not null
created_at      timestamptz not null
last_seen_at    timestamptz not null
disabled_at     timestamptz null
```

`status` 只允许 `active` 和 `disabled`。

### `daily_client_quotas`

```text
client_id       uuid not null
quota_date      date not null
success_count   smallint not null default 0
reserved_count  smallint not null default 0
updated_at      timestamptz not null
primary key (client_id, quota_date)
```

### `daily_ip_quotas`

```text
ip_hash         bytea not null
quota_date      date not null
success_count   smallint not null default 0
reserved_count  smallint not null default 0
updated_at      timestamptz not null
primary key (ip_hash, quota_date)
```

网络地址使用服务端密钥和配额日期进行 HMAC-SHA-256，不保存明文地址。按日期加入摘要输入，使不同日期的地址摘要无法直接关联。

### `generation_requests`

```text
id               uuid primary key
client_id        uuid not null
request_key      text not null
ip_hash          bytea not null
requested_count  smallint not null
reserved_count   smallint not null
success_count    smallint not null default 0
status           text not null
error_code       text null
expires_at       timestamptz not null
created_at       timestamptz not null
completed_at     timestamptz null
unique (client_id, request_key)
```

请求表不保存提示词、参考图或生成图片。完成后只保留结算和诊断所需的元数据。

## 核心机制：事务预占与按成功结算

### 预占流程

1. 验证匿名设备、来源、请求参数和 `requestKey`。
2. 读取 Cloudflare 传递的访客地址并计算当日地址摘要。
3. 在一个 PostgreSQL 事务中按 `(client_id, request_key)` 插入请求行；并发重复请求通过唯一约束等待首个事务完成，再读取已有请求。
4. 先锁定生成请求行，再创建或读取设备额度与地址额度行。
5. 始终按“生成请求行、设备额度行、地址额度行”的顺序执行 `SELECT FOR UPDATE`，预占、结算和过期回收都必须遵守相同顺序。
6. 检查设备剩余额度和地址剩余额度，同时增加两张额度表的 `reserved_count`。
7. 提交事务后再调用上游接口，数据库事务不能覆盖耗时的网络请求。

PostgreSQL 行锁保证同一设备或地址的并发请求串行完成额度判断，避免多个请求同时看到旧余额。统一锁顺序避免预占、结算、过期回收和重复提交之间形成锁等待环。

### 上游调用

服务端按请求数量创建最多 4 个生成槽位。每个槽位独立调用一次现有 OpenAI 兼容接口，因此部分图片成功时可以精确结算，也能沿用当前前端的单槽失败与重试体验。

参考图编辑只接收本次上传的图片，不接受用户提供任意远程网址。服务端复用已解析的上传文件构造各槽位请求。

### 结算流程

1. 汇总实际成功槽位数量。
2. 在新事务中锁定生成请求、设备额度和地址额度。
3. 从两张额度表释放该请求的全部预占数。
4. 将实际成功数增加到两张额度表的 `success_count`。
5. 将请求更新为 `completed`、`partial` 或 `failed`。
6. 返回每个槽位的结果和结算后的额度。

同一请求只能结算一次。重复的完成回调必须读取已完成状态并直接返回，不能再次修改额度。

### 过期预占

上游请求超时小于预占有效期，建议上游超时为 180 秒，预占有效期为 10 分钟。接口服务启动时和固定短周期内扫描过期的 `reserved` 或 `running` 请求，在事务中将它们标记为 `expired` 并释放对应预占。

如果数据库不可用，生成请求直接失败，不能绕过额度调用上游。服务进程退出时无法完成的请求由过期回收机制处理。

## 接口设计

### 会话与额度

```text
GET /api/session
GET /api/quota
```

`GET /api/session` 在需要时签发匿名 Cookie，并返回公众模式、允许的模型展示名、参数范围、当前额度和重置时间。`GET /api/quota` 用于生成后或页面恢复前台时刷新额度。

额度响应：

```json
{
  "limit": 10,
  "used": 3,
  "reserved": 0,
  "remaining": 7,
  "resetAt": "次日北京时间零点对应的 ISO 8601 时间"
}
```

### 文生图

```text
POST /api/images/generations
Content-Type: application/json
```

```json
{
  "requestKey": "客户端生成的唯一请求号",
  "prompt": "图片描述",
  "count": 2,
  "size": "1:1",
  "quality": "standard"
}
```

### 参考图编辑

```text
POST /api/images/edits
Content-Type: multipart/form-data
```

表单包含 `requestKey`、`prompt`、`count`、`size`、`quality` 和最多 4 个参考图文件。

### 生成响应

```json
{
  "requestId": "服务端请求号",
  "results": [
    {
      "index": 0,
      "status": "success",
      "image": {
        "mimeType": "image/png",
        "data": "base64..."
      }
    },
    {
      "index": 1,
      "status": "failed",
      "errorCode": "PROVIDER_REJECTED"
    }
  ],
  "quota": {
    "limit": 10,
    "used": 4,
    "reserved": 0,
    "remaining": 6,
    "resetAt": "次日北京时间零点对应的 ISO 8601 时间"
  }
}
```

部分成功仍返回 200，由 `results` 表达各槽位状态。整个请求在预占前失败时使用对应的 HTTP 状态码。

### 健康检查

```text
GET /health/live
GET /health/ready
```

存活检查只确认进程运行；就绪检查确认数据库可连接并且关键配置完整，不调用付费上游接口。

## 参数与文件校验

- 单次生成数量为 1 到 4。
- 提示词不能为空，最大 4000 个字符。
- 比例、质量和模型只能取服务端白名单值。
- 参考图最多 4 张，单张最大 10MB，总计最大 20MB。
- 参考图只允许 JPEG、PNG 和 WebP。
- 不能仅根据扩展名或请求中的 MIME 类型判断文件格式，必须检查文件内容。
- 解码后检查图片宽高和总像素，拒绝异常尺寸与图片解压攻击。
- 不接受用户指定上游地址、密钥、模型标识或任意远程参考图网址。
- 上游返回数据设置最大允许大小，超过限制按上游异常处理并释放额度。

## 错误模型

服务端对外使用稳定错误码，不直接转发上游完整响应：

```text
QUOTA_EXHAUSTED       设备今日额度用完
IP_QUOTA_EXHAUSTED    当前网络今日试用额度用完
RATE_LIMITED          操作过快
INVALID_REQUEST       请求参数无效
INVALID_IMAGE         参考图格式或尺寸无效
REQUEST_TOO_LARGE     上传内容过大
PROVIDER_REJECTED     上游拒绝请求
PROVIDER_TIMEOUT      上游超时
SERVICE_UNAVAILABLE   数据库或关键依赖不可用
PUBLIC_GENERATION_OFF 免费生图已临时关闭
```

额度不足和频率超限返回 429；请求无效返回 400；上传过大返回 413；上游异常返回 502 或 504；服务不可用返回 503。用户界面根据错误码显示中文提示。

## 公众模式与现有模式

项目增加明确的部署模式：

```text
self-hosted  现有浏览器直连模式
public       服务端代理与匿名额度模式
```

自部署模式保持当前行为。公众模式通过构建变量选择，但所有密钥只能存在于接口服务的运行时环境变量中，不能写入任何 `VITE_` 变量。

前端新增统一的生图客户端边界：自部署模式调用现有浏览器直连实现，公众模式调用同域名 `/api/images/*`。页面和画布节点都使用该边界，不在各组件中分别判断部署模式。

公众模式：

- 默认首页进入生图工作台。
- 隐藏视频、音频、文本模型、WebDAV、渠道密钥配置和本地 Codex 助手。
- 保留生图、画布、素材、生成记录、提示词库和导入导出。
- 模型展示名、比例、质量和数量范围从 `/api/session` 获取。
- 页面常驻展示今日剩余额度。

隐藏必须发生在路由和功能配置层，不能只用 CSS 遮挡入口。

## 手机端设计

### 导航

桌面继续使用顶部导航。手机使用固定底部导航，只保留“生图、画布、素材”。生成记录放在生图页右上角，提示词库从提示词输入区打开。

### 生图工作台

- 顶部显示标题、今日剩余额度和生成记录入口。
- 中部依次展示提示词、参考图和生成结果。
- 底部固定生成操作区，包含数量、比例和生成按钮。
- 质量等次要参数放入底部抽屉。
- 生成结果使用双列网格，点击进入全屏预览。
- 全屏预览提供下载、保存到素材、加入参考图和插入画布。
- 参考图选择同时支持手机相册和拍照。
- 主要触控区域不小于 44 像素。
- 适配顶部和底部安全区域，软键盘不能遮挡输入区和主操作按钮。

### 无限画布

- 单指拖动节点，单指拖动画布空白区域。
- 双指缩放和移动画布。
- 点击节点后显示底部节点工具栏，不依赖悬停状态。
- 放大连接点和缩放控制点的可触摸区域。
- 长按打开节点操作菜单。
- 提示词、生成参数和节点信息使用底部抽屉。
- 手机默认隐藏小地图，将工具栏收敛为添加、撤销、重做和更多。
- 系统页面缩放和画布缩放不能相互抢占。
- 生成过程中仍允许移动和缩放画布。

### 本地数据提示

首次使用时说明作品保存在当前设备，清理浏览器数据或更换设备不会自动同步。保留现有画布导出，并补充面向公众用户的一键备份入口。重要图片始终提供直接下载。

## 可安装网页应用

- 增加网页应用清单、完整图标、主题色和启动显示配置。
- 支持从手机浏览器添加到主屏幕。
- 服务工作线程只缓存网页外壳和必要静态资源。

## 安全与防刷

### 来源地址

Cloudflare 通过 `CF-Connecting-IP` 向源站传递访客地址。该请求头只有在源站确认请求来自 Cloudflare 时才可信，因此源站防火墙只允许 Cloudflare 地址段访问公开端口。应用不信任任意客户端传入的 `X-Forwarded-For`。

Nginx 和应用日志记录 `Cf-Ray`，便于关联 Cloudflare 与源站请求。网络地址只以当日 HMAC 摘要进入配额表和应用日志。

### 请求频率

Nginx 对 `/api/images/generations` 和 `/api/images/edits` 按真实来源地址限制为平均每分钟 5 次，并允许少量瞬时突发。频率限制只防短时请求洪峰，数据库额度仍是最终扣减依据。超限统一返回 429。

### 同源与密钥

- 接口不开放宽泛跨域访问。
- 写接口校验 `Origin` 与站点配置一致。
- Cookie 使用安全属性，前端 JavaScript 无法读取匿名令牌。
- 上游地址、密钥和模型真实标识只存在于接口服务环境变量。
- 公众构建产物和前端接口响应中不包含上游密钥。

### 内容与日志

- 继续使用现有上游的内容安全能力，不手写简单关键词表冒充内容审核。
- 对上游安全拒绝使用统一错误码，不向用户暴露内部响应。
- 默认不记录提示词、参考图、生成图片、原始网络地址和 Cookie。
- 记录请求号、匿名设备内部编号、当日地址摘要、耗时、成功数和错误类别。
- 页面展示简短的使用规则、数据保存说明和隐私说明。

### 费用风险

按用户决定，第一阶段不设置全站每日图片总量上限。因此系统不能提供绝对费用上限：能够持续更换设备和网络地址的攻击者仍可能扩大消耗。

必须保留以下止损能力：

- `PUBLIC_GENERATION_ENABLED` 运行时开关，可在不重新构建前端的情况下停止新生成。
- 上游余额或消费告警。
- 生成成功率、调用量和异常突增告警。
- 单设备、单地址和短时频率限制。

关闭免费生图时，用户仍可打开、导出和下载已有的本地内容。

## 部署设计

现有单一 Nginx 静态镜像调整为两个应用容器：

```text
web  Nginx 静态页面，并将 /api 和 /health 转发到 api
api  Bun 接口服务，仅在 Docker 内部网络监听
```

接口服务复用服务器上现有 PostgreSQL，通过 Docker 网络或受限的数据库地址连接，不在本项目 Compose 中重复创建 PostgreSQL。

关键环境变量：

```text
DATABASE_URL
AI_BASE_URL
AI_API_KEY
AI_MODEL
ANON_TOKEN_SECRET
IP_HASH_SECRET
PUBLIC_GENERATION_ENABLED=true
DAILY_DEVICE_LIMIT=10
DAILY_IP_LIMIT=30
QUOTA_TIMEZONE=Asia/Shanghai
PUBLIC_ORIGIN
UPSTREAM_TIMEOUT_MS=180000
RESERVATION_TTL_SECONDS=600
```

`api` 不映射公网端口。数据库迁移作为独立部署步骤执行，迁移成功后再启动新接口版本。部署时先完成向后兼容的表结构，再切换前端公众模式；回滚时可先关闭公众生图并恢复旧前端，自部署模式数据不受影响。

## 生命周期与异常场景

### 首次访问

页面调用 `/api/session`，服务端签发匿名 Cookie 并返回额度。Cookie 写入失败时页面可以浏览，但生成按钮不可用，并提示需要允许站点 Cookie。

### 正常生成

前端生成 `requestKey`，服务端预占设备与地址额度，调用上游并按实际成功数结算。前端把成功图片保存到 IndexedDB，并使用响应中的最新额度更新界面。

### 手机网络重试

同一 `requestKey` 的重复请求不重复预占。若原请求仍在运行，返回运行状态；若已经完成，返回已完成状态和额度。由于第一阶段明确不在服务端保存生成图片，接口不能重放已经丢失的图片响应：如果上游已经成功并完成扣减，但最终响应在网络中断时丢失，客户端只能得知请求已经完成，无法重新取回该图片。这是“不保存服务端图片”决策下接受的剩余风险，后续若需要完整恢复能力，必须增加有过期时间的服务端图片暂存。

### 清除 Cookie

浏览器获得新匿名设备额度，但仍受当日网络地址 30 张限制。由于不注册且不启用人机验证，系统明确接受用户更换网络地址后可能绕过限制这一剩余风险。

### 共享网络

家庭、公司或校园中的多个设备共享 30 张网络地址额度，可能在各自设备尚有余额时触发地址额度不足。界面需要区分设备额度和网络试用额度，不把地址限制错误显示为个人额度用完。

### 上游部分成功

成功槽位正常扣减并返回，失败槽位释放预占。前端展示成功图片和失败槽位的重试按钮，重试创建新的 `requestKey` 并按新的请求重新预占。

### 服务中断

服务进程重启后回收已过期预占。未过期请求在没有持久任务执行器的情况下不会自动恢复上游调用，最终由过期流程释放。客户端可在请求明确失败或过期后重新发起。

## 验证方案

### 配额与并发

- 同一设备并发申请超过 10 张时，成功数与预占数之和始终不超过 10。
- 同一地址下多个设备并发申请时，总成功数与预占数始终不超过 30。
- 部分成功只扣成功槽位，失败与超时释放预占。
- 同一 `requestKey` 重复提交不重复扣减。
- 过期请求只释放一次，完成请求不能再次结算。
- 北京时间零点前后使用不同配额日期，旧日期记录不影响新一天。

### 安全与输入

- 伪造 `CF-Connecting-IP` 的直连请求无法到达源站公开服务。
- 跨站写请求被来源校验拒绝。
- 超长提示词、超量参考图、伪造图片、异常像素和超大请求被拒绝且不预占额度。
- 数据库不可用时不会调用上游。
- 前端构建产物、接口响应和日志中不存在上游密钥。
- 日志中不存在提示词、图片内容、Cookie 和明文网络地址。

### 前端与移动端

- 公众模式只显示生图、画布、素材和相关辅助入口。
- 自部署模式保持现有模型配置与浏览器直连能力。
- iPhone Safari 和 Android Chrome 可以上传、拍照、生成、预览、下载及插入画布。
- 软键盘、刘海和底部手势区不遮挡主要操作。
- 单指节点操作、空白画布移动和双指缩放不会互相冲突。
- 安装到主屏幕后可正常启动；断网只能打开已缓存外壳，不能误报可离线生图。

### 故障与运维

- 上游超时、拒绝、返回异常数据和部分成功都有稳定错误码。
- 关闭 `PUBLIC_GENERATION_ENABLED` 后立即拒绝新生成，但本地内容仍可使用。
- 接口重启后能够回收过期预占。
- Nginx 超限返回 429，并能通过 `Cf-Ray` 关联请求日志。

## 已确认决策

- 手机端路线为“先做手机浏览器和可安装网页应用，后续再上应用商店”。
- 使用自有服务器和已有 PostgreSQL。
- 使用已有稳定的 OpenAI 兼容生图接口。
- 第一阶段预计每天访问人数不超过 100。
- 每个匿名设备每天成功生成 10 张，按北京时间零点重置。
- 失败不扣额度，多张生成按实际成功张数扣减。
- 域名已经接入 Cloudflare，但试用期不启用人机验证。
- 网络地址辅助额度为每天 30 张。
- 第一阶段不设置全站每日生成总量上限。
